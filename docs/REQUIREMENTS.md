# وثيقة المتطلبات (Requirements Specification)

## 1. المتطلبات المعمارية والتقنية (Technical Requirements)

### 1.1 القيود الصارمة (Strict Constraints)
- **Static Web Only:** يجب أن يعمل الموقع بالكامل كملفات ثابتة دون أي كود خادم (No Node.js Backend, No PHP, No Python servers, No DB engines).
- **GitHub Pages Ready:** يجب أن يكون الموقع متوافقاً تماماً مع الاستضافة في GitHub Pages بدون مسارات مطلقة تكسر الربط.
- **Pure Web Stack:** استخدام HTML5 الدلالي، CSS3 النقي (Vanilla CSS)، وجافاسكريبت النقية (Vanilla ES6+ JavaScript).
- **No Heavy Frameworks:** يمنع استخدام أطر عمل ضخمة (مثل React أو Vue أو Angular أو Tailwind) إلا إذا طُلب ذلك صراحة، لضمان البساطة والسرعة القصوى.
- **Offline & Local Friendly:** يجب أن يقرأ التطبيق ملفات البيانات عبر مسارات نسبية (`./data/...`).

### 1.2 توافق المتصفحات والأجهزة
- دعم جميع المتصفحات الحديثة: Chrome, Edge, Safari, Firefox.
- دعم كامل للشاشات المتنوعة: الهواتف الذكية (Small screens)، الأجهزة اللوحية (Tablets)، وشاشات الحواسيب المكتبية (Desktops/Laptops).

## 2. المتطلبات الوظيفية (Functional Requirements)

### 2.1 إدارة وتصفح المواد (Courses & Lectures)
- عرض قائمة المواد الدراسية المسجلة في `data/courses.json`.
- إمكانية الدخول إلى صفحة تفاصيل المادة لرؤية المحاضرات وبنوك الأسئلة والنماذج التابعة لها.
- البحث السريع والتصفية حسب اسم المادة أو الكود أو المحاضرة.

### 2.2 بنوك الأسئلة (Question Banks)
- تجميع الأسئلة في بنوك مصنفة حسب المحاضرة أو بنوك شاملة (Mixed/General).
- إظهار تفاصيل كل بنك: عدد الأسئلة، المحاضرات المشمولة، ومستوى الصعوبة المتوقع.
- إمكانية تشغيل أي بنك أسئلة كاختبار تدريبي حر.

### 2.3 النماذج والاختبارات النصفية (Models & Midterms)
- نماذج تدريبية محددة بعدد أسئلة ووقت اختياري أو إلزامي.
- قسم خاص بالاختبارات النصفية (Midterm Exams) يقدم نماذج متكاملة تحاكي الاختبار الفعلي (Model A, Model B, etc.).
- بدء الاختبار بضغطة زر واحدة دون الحاجة لإعدادات معقدة.

### 2.4 محرك الاختبارات التفاعلي (Interactive Quiz Engine)
- عرض الأسئلة سؤالاً بسؤال مع شريط تقدم (Progress Bar) ونسبة إنجاز.
- دعم أنواع الأسئلة:
  1. اختيار من متعدد (Multiple Choice).
  2. صح وخطأ (True/False).
  3. اختيار متعدد الإجابات (Multiple Select).
  4. ملء الفراغ (Fill in the Blank).
- إمكانية التنقل بين الأسئلة (السابق / التالي) وتعديل الإجابة قبل التسليم.
- مؤقت زمني اختياري مع تنبيه عند اقتراب انتهاء الوقت وتسليم تلقائي عند الصفر.
- زر تسليم الاختبار (Submit Quiz) مع نافذة تأكيد في حال وجود أسئلة غير مجاب عنها.

### 2.5 التصحيح وحساب النتائج (Grading & Analytics)
- تصحيح تلقائي فوري بعد الضغط على تسليم الاختبار.
- حساب:
  - عدد الإجابات الصحيحة.
  - عدد الإجابات الخاطئة.
  - عدد الأسئلة التي لم يتم الإجابة عليها.
  - الدرجة الإجمالية والنسبة المئوية (مثال: 18/20 - 90%).
  - الوقت المستغرق في الاختبار.

### 2.6 مراجعة الإجابات والمصادر (Review Mode)
- استعراض شامل لجميع أسئلة الاختبار بعد التسليم.
- توضيح إجابة الطالب مقابل الإجابة الصحيحة مع تلوين دلالي (أخضر للصحيح، أحمر للخطأ).
- تقديم شرح وافٍ لسبب صحة الإجابة.
- إظهار **مصدر السؤال بدقة** (المادة، المحاضرة، الصفحة، القسم).

### 2.7 تخزين البيانات المحلية (Local Storage)
- حفظ سجل نتائج الاختبارات السابقة محلياً على جهاز الطالب.
- إمكانية مراجعة النتائج السابقة في صفحة الحساب/السجل المحلي.
- حفظ تفضيلات المستخدم (مثل الوضع الليلي/النهاري).

## 3. متطلبات جودة المحتوى (Content Integrity Requirements)

- **القاعدة الذهبية:** المحاضرات هي المصدر الوحيد للمعلومات والأسئلة.
- يُمنع صياغة أسئلة من الذاكرة العامة أو الإنترنت أو مواد غير مضافة.
- ربط كل سؤال بمصدره الدقيق في مستند المحاضرة.
- خلو الأسئلة من التكرار والغموض والتناقض.
